# C1 전공 · 커리어 — 카테고리 지시

> 전공 공부 · 공개 학습 사이트 · AI 공부 · 반도체 분석 · 커리어 주제의 세션에만 실린다(`C:\C1_Career\CLAUDE.md`가 `@`로 부름). 뼈대(`<core>\skeleton\skeleton.md`)에 있는 것은 여기 다시 쓰지 않는다.

## 공개 학습물
- 사용자를 소개할 때는 사용자가 정한 한 줄 소개를 그대로 쓰고, 옛 문서에서 다른 표현이 보이면 고친다.
- 공부 워크스페이스는 private에 두고, 공개는 따로 둔 repo · 폴더로 증류분만 낸다.
- 공개 콘텐츠는 사용자가 이해한 것만 증류한다. Claude가 앞서 채워 넣지 않는다. 예외로 먼저 낸 것은 그렇다고 표시해 둔다.
- 사용자의 hands-on(UVM · RTL · 핸즈온 단계)에서 설계 결정 칸(transaction 필드, scoreboard 기대값, next-state 표 등)은 비워 두고 사용자 몫이라 적는다. Claude는 골격 · 반복 코드 · 골든 모델까지만 만들고, 더 도와 달라는 요청에도 그 칸은 채우지 않는다.
- 코덱 · HW 공개 경계의 판별식은 "공개 자료만으로 아무 엔지니어나 도출할 수 있는가"다. 공개 spec · 오픈소스에서 도출한 HW 정량(SRAM · MAC · 대역폭 추정)까지 공개하고 실제 RTL 코드만 비공개로 둔다. Claude가 더 닫힌 쪽을 추천할 때마다 사용자는 공개 쪽을 골랐으니 스스로 검열하지 않는다(정말 특별한 아이디어만 공개 전에 묻는다).
- 정답이 있는 콘텐츠(퀴즈 · 문항)는 공개 전에 정답을 가린 사본으로 다시 풀어 대조한다. 수치 검산은 공식을 쓰지 않는 경로(완전 열거 · 수치적분)로 짜고, 고친 뒤 재검산은 LLM 재감사가 아니라 script 재계산으로 한다.
- 외부 자료 링크는 확인된 URL만 넣는다(응답 200, 영상은 oEmbed로 채널까지). 확인 못 한 것은 검색 링크로 남긴다.
- 학습 앱은 바닐라 엔진 하나 + 데이터 파일(`content.js` · `manifest.json`)로 나누고, 공부가 늘면 데이터만 고친다.
- 빌드형 SPA(React · Vite)를 Actions로 Pages에 처음 낼 때는 `npm ci` 대신 `npm install`을 쓰고(Windows lockfile이 Linux runner와 어긋남), 새 repo는 첫 push 전에 Pages를 `build_type=workflow`로 켠다.

## 공부 세션
- 공부 기록은 Claude가 세션 중에 받아 적는다: Claude의 질문 · 사용자의 답(원문 그대로, 물음표까지) · 정교화를 칸을 나눠서. 양식만 두면 사용자 칸은 비어 버린다. 튜터가 덧붙인 설명도 요약하지 않는다.
- 사용자가 답하지 않은 자율 라운드의 내용은 "사용자 도출 아님"으로 표시한다. 공개 증류에서 무엇이 사용자의 것인지 가르는 근거다.
- 자격시험 범위는 공식 출제기준 · 공식 1차 소스로 커버 표를 만들어 잡고 기출은 경향 보조로만 쓴다. 시험 직후에는 문제를 복원해 기존 자산과 맞대어 GAP과 과투자를 함께 본다.

## init에서 더할 것
- 질문 둘 가운데 하나는 공개 층이다: 공부 · 작업은 private, 공개는 증류분만. 어느 산출물이 공개 후보인지.
- 이해 줄에 "사용자가 도출할 칸"(설계 판단 · hands-on 결정 칸)과 "Claude가 채울 칸"을 가른다.
- 완료 조건에 경력 자산으로 꺼낼 산출물(공개 글 · 앱 · 이력서 한 줄)을 하나 넣는다.
- 항목 하나를 깊이 이해하는 일이면 `wf-study-session`의 전문가 모드를 가져간다.

## wrap에서 더할 것
- 이번 세션의 내용 가운데 "사용자 도출 아님"인 것이 공개 후보에 섞였는지 본다.

## 자산 안내 (새로 만들기 전에 먼저 본다)
전체 목록은 지도(`~/.claude\workflow\maps`), 모르면 `/wf-help`.
- core(모든 세션, 이름만 말하면 skill이 부름): `/wf-help`(사용법 · 프로젝트 소개) · `/wf-ask`(지난 지식) · `/wf-idea` · agent `wf-researcher`(출처 붙은 조사) · `wf-second-look`(판단이 든 결과를 다른 눈으로).
- pool(주제로 복사, `<core>\pool\`): `c1\skills\wf-study-session`(공부 세션 — 시험 모드 · 전문가 모드) · `c1\skills\wf-publish-gate`(공개 학습물 정확성 gate) · `c1\skills\wf-explainer-video` + agent `c1\agents\wf-explainer-maker`(한 장 그림 + 해설 영상, 나중에 publish로 합쳐짐) · `c1\skills\wf-paper-study-app`(자료 → 노트 → 학습 앱) · `common\skills\wf-equity-scenario-app`(기업 하나 → 시나리오 앱, 반도체 기업 분석) · `common\agents\wf-ui-qa`(실제 입력 화면 시험) · `common\skills\wf-pages-deploy`(github.io 배포).
- script: pool `common\tools\` — 화면 시험 `screen-test\check.mjs`(패키지 없는 CDP, PDF 포함) · Pages 배포 `pages-deploy\deploy.py`(경로만 stage, 기본 dry-run) · `serve\serve.ps1`(폰 · LAN 보기). 설치된 공용 도구 `~/.claude\workflow\tools\` — `check.py`(완료 조건) · `redact_check.py`(공개 금지어 gate).
- 주제 안에 있는 판: blind 사본 생성 `C:\C1_Career\<topic>` · 공개 학습 챕터 규약(UVM Lab) `C:\C1_Career\<topic>` · EDA 래퍼 일곱(verilator · yosys · sby · verible · slang · vcd) `C:\C1_Career\<topic>` — RTL 주제에서 두 번째로 쓰이면 pool로 올린다.
