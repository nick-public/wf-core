# C2 학습 — 카테고리 지시

> 가족 학습 앱 · 아이 과제 지원 · 사용자의 성인 학습 트랙 세션에만 실린다(`C:\C2_Learn\CLAUDE.md`가 `@`로 부름). 뼈대(`<core>\skeleton\skeleton.md`)에 있는 것은 여기 다시 쓰지 않는다.

## 학습 판정 (간격 반복 · 레벨이 있는 앱)
- 졸업 · 승급 · 레벨 이동은 산출형 시험으로만 판정한다: 첫 만남과 인출을 가르고, 서로 다른 날 정답 2회를 요구하며, 4지선다 알아보기 · 자기평가 · 소개 직후 정답으로 졸업시키지 않는다. Claude의 첫 판은 자주 이 반대로 간다.
- 사용 신호(정답률 · "안다" 비율)는 점검을 제안만 하고, 이동은 점검 통과로 한다. 졸업 뒤에는 +30일 · +90일 점검을 예약하고 틀리면 졸업을 취소한다.
- 시험 · 연습 · 점검 모드는 SR 필드(다음 복습일 · 졸업)를 바꾸지 않는다. 활동량은 따로 세고, smoke가 "시험 뒤 SR 필드 무변경"을 직접 본다.
- 범위가 정해진 시험 직전 드릴에는 정답 보기 토글을 두고, 본 문항은 틀림으로 센다(사용자). 오개념 카드 · 피드백 문구에 정답 문자열이 새는지 저작 전에 검사한다.

## 아이와 과제
- 아이를 테스터 · 근거 수집 통로로 쓰지 않는다("아이에게 물어봐 달라 · 다음 학년을 열어 보게 해 달라 · 사용을 관찰해 적어 달라"를 제안하지 않는다). 우선순위는 교육과정 대조 · 실동작 검증으로 정한다. 사용자가 일상에서 본 것은 근거로 써도 된다.
- 학교 과제(탐구 · 수행평가 · 논술)에서 학생이 판단 · 발견할 칸은 채우지 않는다. 완성 답안 · 결론 파일 대신 여러 방향의 예시와 접근 안내를 주고, 예시에도 가짜 숫자 대신 빈칸을 둔다. 더 도와 달라고 해도 흐름 문단은 쓰지 않는다.
- 예외는 마감이 코앞일 때 하나다: 부모가 AI와 먼저 완주하고 학생은 따라가며 이해 · 설명한다. 이때 모범 예시 트랙과 학생 트랙의 규칙(초안 금지 등)을 섞지 않는다.
- 자녀용 산출물(앱 · 영상)에는 내용 다음 순서로 "AI로 어떻게 만들었나"(처음 부탁한 말 · 라운드별 요청과 수정)를 보이는 탭이나 장면을 둔다.

## 콘텐츠
- AI가 쓰는 인물 · 역사 이야기는 사실 · 해석 · 전승 · 기록 없음을 갈라 적고, 비유는 "교육 가공"이라 밝힌다. 사용자의 통검토 "all ok"를 해석 하나하나의 확인으로 보지 않는다.
- 시뮬레이션은 외부 sim(PhET)이 강한 개념만 임베드하고, 빈 곳은 자체 SVG로, 둘 다 안 맞으면 영상 · 그림으로 정직한 후크를 둔다. 끝은 문제로 착지한다. GeoGebra는 쓰지 않는다(사용자). 새 외부 도구는 한 단원에서 먼저 시범한다.
- 지도 · 그림은 손으로 그리지 않는다. 지도는 Leaflet + OSM · Commons 지도 위에 좌표만 얹고, 직접 그리는 것은 실자료가 못 하는 설명 도식뿐이다.
- 외부 자료 링크는 확인된 URL만 넣는다(응답 200, 영상은 oEmbed로 채널까지). 확인 못 한 것은 검색 링크로 남긴다.

## 만드는 리듬
- 새 앱은 첫 판을 묻지 않고 끝까지 만들어 보이고, 피드백 뒤의 판은 최종 수준으로 2~3회 안에 끝낸다.
- 단원 · 편 · 과목처럼 되풀이하는 제작은 견본 한 단위가 사용자 확인을 통과할 때까지만 결정을 하나씩 묻고, 그 뒤 양산은 묻지 않고 완주한다.
- 완료는 필드를 채운 것이 아니라 사용자가 지정한 견본 한 페이지의 수준이다. 배치가 끝나면 견본의 요소마다 개수를 세어 맞춘다.
- skill · 제작 파이프라인은 추상 Q&A로 설계하지 않는다. 시범 한 번을 끝까지 돌린 실행에서 뽑고, 둘째 실행이 skill만으로 돌면 확정한다.
- AI가 대량으로 만든 문항 · 단원의 LLM 감사는 한 번 돌고 고치고 끝낸다(재감사를 반복하면 끝없이 시간이 든다). 같은 층의 결함이 두 번 재발한 층만 셀 수 있는 검사로 내리고, 그 검사기는 결함을 심어 잡는지 시험한다. 정답 검산은 공식을 쓰지 않는 경로의 script 재계산으로 한다.
- 데이터가 엔진을 움직이는 앱에서는 빌드 · gate 통과가 정상의 증거가 아니다. 생성기 · 이중 사본 · 설정 플래그마다 넣은 수와 나온 수를 맞춘다(조용한 누락이 흔하다).
- 생성 미디어 API(TTS · 이미지)는 파이프라인을 짜기 전에 한 건으로 결제 등급과 실제 한도를 실측한다(결제 오류 · 무료 등급 없음 · 콘솔과 다른 한도가 흔하다).
- 오래 쓸 가족 도구는 사람의 수동 입력 고리(아이 결과 회수 등)에 기대지 않는다. 루프는 앱 안에 넣고, 기록은 30초 이하로, 수치 규칙은 실사용을 본 뒤에 정한다.
- 앱의 AI 위치는 기본 방침 없이 앱마다 정한다(누가 쓰나 · 비용 · 키 위치). 아이 기기에 부모 키는 두지 않는다. 런타임 AI는 자유 채팅창이 아니라, 사용자가 목적을 고르면 앱이 자기 데이터로 프롬프트를 조립하고 출력 형식을 계약해 받는다.
- 학습 앱은 바닐라 엔진 하나 + 데이터 파일로 나누고, 공부가 늘면 데이터만 고친다.

## 기기 · 배포
- 기기는 트랙마다 다를 수 있다(예: iPhone과 Android). 무서버 localStorage 앱은 처음부터 내보내기 · 복원을 두고(iPhone 기록 삭제 위험), 기기 기능은 iOS 홈 화면 PWA에서 되는지 먼저 본다. 매일 알림은 APK가 맡는다.
- APK는 TWA가 아니라 WebViewAssetLoader로 감싸고, API 키 허용 목록에 `https://appassets.androidplatform.net/*`를 더한다.
- 서비스 워커는 네트워크 우선으로 짠다(폰트 · 외부 라이브러리만 캐시 우선). "고쳤는데 안 바뀐다"면 사용자가 보는 코드가 최신인지부터 본다.
- 반영은 소비처(github.io 폴더 · APK)마다 따로다. Pages는 push 뒤 약 80초가 걸리니, 캐시를 깨는 쿼리로 서빙 파일의 새 마커를 유한 폴링해 확인한다.
- 소스(한글 폴더)와 배포(영어 slug) 트리 모양이 다른 앱은 링크 검사를 배포본에서 하고, 배포에서만 고친 파일은 다음 복사 전에 소스로 되돌린다.
- Supabase 403(`permission denied for table`)은 RLS보다 테이블 GRANT부터 본다. SQL Editor로 만든 테이블에는 붙지 않으니 스키마 SQL에 GRANT를 함께 넣는다.
- 빌드형 SPA(React · Vite)를 Actions로 Pages에 처음 낼 때는 `npm ci` 대신 `npm install`을 쓰고, 새 repo는 첫 push 전에 Pages를 `build_type=workflow`로 켠다.

## init에서 더할 것
- 질문 둘 가운데 하나는 아이 노출이다: 공개 여부 · 아이 기기에서 쓰나 · 아이 이름 · 학교가 산출물에 들어가나.
- 이해 줄에 "누가 쓰나: 아이가 직접 / 사용자가 아이를 위해"를 넣는다. 아이가 직접 쓰는 것이면 아이가 혼자 다시 열 수 있는 길(폰 홈 화면 · 링크 한 개)을 완료 조건에.
- 기록은 아이별 폴더로 가른다.

## wrap에서 더할 것
- 아이에게 보일 산출물이면 "AI로 어떻게 만들었나" 탭 · 장면이 있는지 본다(아이에게 방법을 전한다는 목표).

## 자산 안내 (새로 만들기 전에 먼저 본다)
전체 목록은 지도(`~/.claude\workflow\maps`), 모르면 `/wf-help`.
- core(모든 세션, 이름만 말하면 skill이 부름): `/wf-help`(사용법 · 프로젝트 소개) · `/wf-ask`(지난 지식) · `/wf-idea` · agent `wf-researcher`(출처 붙은 조사) · `wf-second-look`(판단이 든 결과를 다른 눈으로).
- pool(주제로 복사, `<core>\pool\`): `c2\skills\wf-exam-review`(오답 → 노트 · 그림 · 연습 → 약점 DB → 재출제) · `c2\skills\wf-perf-prep`(수행평가 형태별 대비) · `c2\skills\wf-learn-app-audit`(배포 전 네 관점 검수, 데이터부터 고침) · `common\agents\wf-ui-qa`(실제 입력 화면 시험) · `common\skills\wf-pages-deploy`(github.io 배포).
- script: pool `common\tools\` — 화면 시험 `screen-test\check.mjs`(앱 시나리오 표본은 `C:\C2_Learn\<topic>`) · Pages 배포 `pages-deploy\deploy.py` · `serve\serve.ps1`. 설치된 공용 도구 `~/.claude\workflow\tools\` — `check.py` · `redact_check.py`(아이 기록 · 비공개 문서 참조도 막는다).
- 주제 안에 있는 판: 바닐라 HTML 정적 검사 `C:\C2_Learn\<topic>`(태그 균형 · 인라인 script · id 참조 · 캐시 버전) — 두 번째로 쓰이면 pool로 올린다.
