# C0 AI-native workflow — 카테고리 지시

> workflow 자체를 다루는 주제(core 정본, 공개 흐름, 여러 세션 운영 설계 등)의 세션에만 실린다(`C:\C0_Workflow_Core\CLAUDE.md`가 `@`로 부름). 뼈대에 있는 것은 여기 다시 쓰지 않는다.
> 사용자의 목표: AI-native workflow 자체의 전문가가 되는 것. 그래서 이 카테고리의 산출물은 사용자가 설명하고 공개할 수 있는 수준이어야 한다.

## core를 고칠 때
- 정본은 `<core>\`, 세션이 읽는 것은 설치본 `~/.claude\`다. 정본만 고치고 설치하지 않으면 어느 세션에도 반영되지 않는다. 고친 뒤 `install.py --check`로 차이를 본다.
- 뼈대 · 카테고리 문서 · 전역 skill · agent를 바꾸면 모든 세션이 바뀐다. 바꿀 줄을 `/wf-review-page`로 보이고 승인받은 뒤 설치한다. pool 항목의 개선은 자율이다.
- 전역 skill · agent는 실제 세션에서 시험한 뒤 설치를 마친 것으로 본다: `claude -p`로 새 세션을 한 번에 하나 띄워, 그 세션이 실제로 읽고 행동이 바뀌었는지를 다른 agent가 판정한다.
- 이름을 바꾸는 개편은 고쳐 쓰지 않고 새로 쓴다. 옛 판은 tag와 `sources:` 경로로만 남기고, 별칭을 두지 않는다.

## 공개
- 이 카테고리의 주제는 기본이 공개 후보다(workflow 자체가 공개 축의 첫 대상). 공개본은 사람 → 사용자, 카테고리는 예시로만, 경로는 일반 경로로 일반화한다. 실제 실패 사례는 공개본에 넣지 않는다.
- 숫자는 근거가 있는 것만, 효과 주장은 시범 전에는 하지 않는다.

## init에서 더할 것
- 이해 줄에 "core의 어느 조각(뼈대 · 전역 skill · agent · 강제 장치 · 공용 도구 · pool)을 바꾸나"를 넣는다.
- 질문 둘 가운데 하나는 공개 깊이(어디까지 일반화해 공개하나)로 쓴다.

## wrap에서 더할 것
- core를 고쳤으면 `install.py --check`, 설치할 차이가 있으면 wf-review-page로 승인을 받는다.
- 이번 일에서 core가 모자랐던 곳을 다른 카테고리보다 먼저 본다(이 카테고리가 core를 고치는 자리다).

## 자산 안내
- core 도구: `<core>\tools\` — `install.py`(설치 · 차이) · `map.py`(지도) · `pool_sync.py`(pool ↔ 주제) · `move_one.py`(열 때 옮기기).
- 공용 도구 설치본: `~/.claude\workflow\tools\` — `check.py` · `redact_check.py` · `review_page.py` · `scan_sessions.py` · `session_start.py`.
- 설계 기록: `<design-notes>\workflow-design.md`(결과물 문서), 이 카테고리를 세운 설계 `<design-notes>\12_core_design.md`.
