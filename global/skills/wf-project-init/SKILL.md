# wf-project-init

**한 프로젝트가 갖출 모양**(사용자 원문): 지식(그 주제의 원천 층 · 해석 층 + 결정 · 이해 기록) + workflow core와의 연결(과정 기록 → wrap의 자기 개선, pool에서 가져온 skill · agent). 이 skill은 그 모양을 짧게 세운다.
**시간:** A와 C가 한 대화에서 끝난다. 조사가 커지면 조사를 첫 프로젝트로 떼고 여기서 멈춘다.

## 0. 어디서 · 어떤 모드
- **카테고리 판정:** cwd가 카테고리 폴더(`C:\C0_Workflow_Core` · `C:\C1_Career` · `C:\C2_Learn` · `C:\C3_Life`, 또는 그 `CLAUDE.md`가 카테고리 문서를 부르는 한 줄뿐인 폴더, 또는 사용자가 카테고리라고 말한 폴더)면 그 바로 아래 kebab-case 주제 폴더(번호 없음)를 만든다. 실제 카테고리 경로는 cwd가 카테고리도 주제도 아닐 때만 쓰고, 어느 카테고리인지 모르면 이해 시트의 `[추론]` 줄로 둔다. 시험 · 시뮬레이션 폴더 안에서 불렸으면 그 밖에 아무것도 만들지 않는다.
- **새로:** cwd가 비었거나 위처럼 새 주제 폴더를 만들 때.
- **업그레이드:** cwd에 `CLAUDE.md`(카테고리 한 줄이 아닌 것) · 재진입 · decisions 중 하나라도 있을 때. 재-Init도 같다.
- **옮기며 업그레이드:** cwd가 카테고리 폴더이고 사용자가 옛 위치의 프로젝트 경로를 함께 주면(예: `C:\C1_Career`에서 "`/wf-project-init <old-workspace>`") 그 프로젝트를 대상으로 업그레이드하고 4절의 이동부터 한다. Windows는 세션 · 터미널이 열려 있는 폴더의 이름을 바꾸지 못하므로, 옮길 프로젝트 안에서 연 세션으로는 옮길 수 없다 — 그때는 이해 시트에 "카테고리 폴더에서 다시 열어 옮긴다"를 다음 첫 행동으로 적고 업그레이드는 옮긴 뒤로 미룬다.
- **카테고리 문서의 "init에서 더할 것" 절을 먼저 읽는다**(카테고리마다 묻는 칸 · 가벼운 판 여부가 다르다).
- 사용자 원문은 `00_META\INIT_<YYYY-MM-DD>.md` 맨 위에 고치지 않고 둔다. 이 파일이 이번 Init의 기록이다.

## 1. Step A — 먼저 읽고, 이해 시트 한 장
읽기는 `wf-project-scout`에게 한 번 맡기고 요약만 받는다(모드 · 주제 경로 · 원문을 넘긴다). **메인은 scout 결과가 오기 전에 주제 폴더의 문서도, 지도도 읽지 않는다**(먼저 읽으면 시간과 맥락을 두 번 쓴다).

이해 시트(`INIT_<날짜>.md` 본문):
1. 맨 위 사용자 원문(불가침).
2. **왜 이 일을 하나** — 원문의 말로 한두 줄. 원문에 없고 다른 문서에서 가져온 이유는 `[추론]`.
3. 이해 줄 일곱 안팎 — 결과물 · 쓰는 사람 · 완료 판정 · 쓰기 경계 · **공개(후보인가, 어느 깊이까지)** · 선례 · 카테고리 절이 요구한 칸. 줄마다 `[원문]` `[선례]` `[추론]`. 사용자가 볼 곳은 `[추론]` 줄뿐이다.
4. 판정: 명확 → B 없이 C / 선례와 비슷 → 차이만 B / 새 종류 → B / 정보 부족 → 필수 입력만 묻는다.
5. **B 깊이 — 시트에 이유와 함께 한 줄로 보인다**(사용자 원문: "step A에서 step B의 깊이를 서로 논의"). 사용자는 이 줄을 고쳐 깊이를 바꿀 수 있다. 가벼움(agent 한두 개) · 깊음(병렬 조사) · **분리**(조사 결과가 분해 · 경계 · 첫 산출물을 바꿀 수 있고 조사 자체가 산출물을 남기면, 조사를 첫 프로젝트로 떼고 Init은 여기서 멈춘다 — 재진입 카드의 다음 첫 행동 = 그 조사, 끝나면 재-Init).

**묻는 것은 최대 둘:** 되돌리기 어려운 칸(공개 범위 · 새 remote · 아이 노출 · 회사 경계 · 폴더 이동)과 사용자만 아는 사실 가운데 가장 갈리는 둘만, 완전한 문장 + 추천값. 나머지 열린 점은 추천값으로 정해 decisions에 `(가정)`으로 적고 시트에는 "가정으로 둔 것" 한 줄 목록으로만 보인다. 그 밖에는 "틀린 줄만 고쳐 주십시오". 질문지 · 선택지 메뉴를 내밀지 않는다. **시트는 `/wf-review-page`로 artifact로 보인다**(사용자가 폰에서 본다).

## 2. Step B — 결정 자료 한 장 (A가 필요하다고 판정할 때만)
- 조사: 내부 자료는 scout가 찾은 경로와 줄로 인용(사본 금지). **외부 사실이 하나라도 필요하면 메인이 직접 웹을 찾지 않고 반드시 `wf-researcher`에게 질문 단위로 맡긴다**(독립인 질문은 동시에, 3개 이하). 1차 출처부터.
- 권장안 하나 + 버린 대안과 이유(그대로 decisions로 옮겨질 모양).
- 분해: 하나로 / 공통 → 분화. 분화면 갈래마다 목표 · 완료 조건 · 공유물의 정본 위치 · "서로 고치지 않는다" 경계 · 합치는 시점.
- **운영 형태(사용자 원문: 프로젝트의 agent system을 정교하게):** 기본 메인 + sub-agent / 단일 세션(설계 · 학습 · 문답이 잦음 · 큰 공유 파일) / workflow(같은 단계를 많은 항목에) / 여러 세션(다른 영역의 긴 일) / 비대화 · 예약(gate · 정기 점검). 고른 형태에서 메인이 직접 할 것 · agent에게 줄 것 · 동시 수 · 시간 예산을 한 줄씩(뼈대 D). 무인 구간이 있으면 그 일의 명령이 settings의 ask에 걸리는지 확인하고, 걸리면 그 앞에서 끝나게 짠다.
- 첫 이정표 = 얇은 끝-끝 하나, 그리고 첫 실제 사용을 완료 조건에. 날짜 · 편수 목표는 첫 측정 뒤.
- **재-Init 시점을 미리 적는다**(사용자 원문: 중간 결과에 따라 방향이 바뀌면 그때 다시 init): "이 결과가 나오면 다시 init" 한두 줄을 재진입 카드에.
- 결정 자료도 `/wf-review-page`로 보인다. 사용자가 내용을 알고 판단할 수 있게 권장안 · 버린 대안 · 분해를 한 장에.

## 3. Step C — 합의와 장착 (세션에 실리는 것만)
짧은 동의는 전체 승인. 그다음 만든다:

| 산출물 | 내용 |
|---|---|
| `CLAUDE.md` 짧은 판 | 왜(사용자 말) · 쓰기 경계 · 정본 위치 · 이 일 고유 gate · 함정 몇 줄 · 경계 표 세 칸. 뼈대 · 카테고리에 있는 말은 쓰지 않는다. 줄마다 "빼면 나빠지나". |
| `00_META\REENTRY.md` | 맨 위 목적 · 최종 목표 / 지금 / 사용자 차례 / **다음 첫 행동**(어느 파일의 무엇까지). 덮어쓰기, 이력은 로그로. 세션이 열릴 때 hook이 이 머리를 보인다. |
| `00_META\decisions.md` | `D-01`부터. 선례에서 가져온 것과 안 가져온 것, `(가정)` 표시. 뒤집으면 superseded. |
| `00_META\checks.yaml` + 완료 조건 | 기계 칸(`python ~/.claude/workflow/tools/check.py 00_META/checks.yaml`) + 사용자 판정 칸. **첫 기계 칸은 이 일의 완료 조건 하나**(파일이 있나가 아니라 결과가 맞나)로 쓴다. 틀어지기 쉬운 해석은 그것을 잡는 검사 한 줄로(글로만 두면 재발한다). |
| 지식 자리 | 도메인 지식이 생길 주제면 `knowledge\`(원천 층 `sources\` · 해석 층, 해석은 원천을 인용) 자리만 만든다. 내용은 일하며 채운다. |
| 첫 일 한두 개 | 재진입 카드 안에, 완료 조건 포함. "계속"이면 돌 수 있게. |
| pool 복사본 | 이 일에 맞는 것만: `python <core>/tools/pool_sync.py copy <pool 항목> <주제 경로>`(origin · base 기록). 바깥 skill은 출처 URL을 origin으로. |
| 공개 후보면 | 완료 조건에 "공개본" 칸 하나와 `LINKS.md`(원본 경로 · 원본 commit · 게시 URL) 자리. 공개 절차는 publish 쪽이 맡는다. |

**만들지 않는 것:** 일반 start · log skill 사본(뼈대와 wrap이 한다), 사람용 README · 계획서 묶음, 손으로 쓴 자산 목록, 지식 사본(지도가 가리킨다), 시범 전의 전용 skill. 업그레이드 모드에서 이미 있는 MASTER_PLAN · README · open_questions는 다시 쓰지 않는다(필요하면 맨 위에 "정본은 REENTRY · decisions" 한 줄).
git repo면 새 주제는 private으로 시작하고(remote 추가는 묻는다), 만든 파일만 경로를 지정해 commit한다.

## 4. 업그레이드 모드에서 더 할 것
- **카테고리 폴더로 옮기기(P0 "열 때 옮기기"):** 주제가 아직 옛 위치(`<old-workspace>` · `<old-workspace>` · `<old-workspace>` · `<other-person-folder>`)에 있으면 이해 시트에 "이동: 지금 경로 → `C:\C?_*\<이름>`"을 넣고 질문 하나로 확인한다(폴더 이동은 따로 승인). 승인되면 `python <core>/tools/move_one.py "<지금 경로>" <C0|C1|C2|C3>`로 계획(dry-run: 바뀔 경로 · 치환 수 · 메모리 키)을 보이고, `--apply`로 옮긴다. script가 원격 없는 repo는 zip으로 먼저 보관하고, 이름 바꾸기가 실패하면(그 폴더를 연 다른 세션 · 터미널 · VS Code) 아무것도 바꾸지 않고 멈춘다. 옮긴 뒤 `--verify`로 옛 경로 문자열이 살아 있는 설정 · script에 남지 않았는지 본다. 되돌리기는 `--undo`.
- 파일을 주인 셋으로 가른다(판정 근거는 주제 폴더를 cwd로 한 `git log --since=60.days --name-only --format=`의 수정 빈도): ① 뼈대 · pool이 맡을 것(일반 start/log 사본, 옛 `/nk:*`를 부르는 마무리 skill) → `pool_sync.py archive`로 `90_Archive/claude/`에(shell `mv`는 `.claude` 아래에서 막힌다) ② 처음만 심은 것(CLAUDE.md · 재진입) → 위 짧은 판으로 새로 쓴다(옛 판은 git에) ③ 그 일 전용(decisions · gate · 전용 skill · 도구) → 그대로.
- "work-os 표준 · profile을 따른다" 선언은 지운다(옛 시스템은 얼렸다).
- pool에 같은 일의 정본이 있으면 이 폴더 판과 비교해, 이 폴더 판이 더 나으면 wrap 때 pool로 올릴 후보로 적는다.
- 얼린 my-kb에 이 주제 전용 함정 · 규격 노트가 있으면 scout가 찾은 것 중 "빼면 나빠지나"를 통과한 것만 CLAUDE.md 함정 줄로 새로 쓴다.
- 재-Init이면 `INIT_<날짜>.md`에 무엇이 바뀌었나(왜 · 완료 조건 · 분해)를 원문 아래 한 줄로.

## 5. 끝
- 지도를 다시 굽는다(묻지 않음, 약 10초): `python <core>/tools/map.py --build`. 새 주제 · 옮긴 주제가 프로젝트 목록에 바로 보이게.
- 사용자에게: 이해 시트 artifact 링크, 정한 것, 사용자 차례, 다음 첫 행동. 길어졌다면 B를 떼었어야 한다는 신호다.
- 이번 Init에서 이 skill이 모자랐던 점은 wrap의 과정 기록에 남긴다(이 skill도 core의 일원이라 wrap이 고친다).
