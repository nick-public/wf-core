# wf-review-page

요구: 사용자가 실체 · 핵심을 쉽게, 빠르게, 재질문 없이 알게 해야 한다. 내용을 모르고 한 승인은 의도와 다르게 흘러간다.

## 1. 판정을 먼저 끝낸다
페이지를 만들기 전에 Claude가 모든 항목의 판정을 끝낸다. 페이지는 **결과**를 보이는 곳이지 판정을 사용자에게 넘기는 곳이 아니다.
- 사용자 표시 칸은 되돌리기 어려운 것 · 사용자만 아는 사실, **둘 이하**. 나머지는 "이렇게 했다 / 하겠다"로 보이고, 전체에 대한 표시 하나(맞음 · 고침)와 자유 메모 하나만 둔다.
- 항목마다 "맞습니까" 칸을 두지 않는다.
- **예외 하나 — 외부 공개본 승인:** 공개는 되돌릴 수 없으므로 실제 결과물 미리보기(게시될 사이트 · 영상)와 공개본 전문을 한 장에 보이고, 사용자는 "게시" 또는 "고침" 하나를 표시한다. 문단 칸은 고칠 곳을 적는 자리이고 모든 문단에 표시를 받지 않는다. Claude는 문단마다 원본 대비 바뀐 곳과 금지어 검사 결과를 먼저 붙인다.

## 2. 페이지 모양
1. 맨 위: 이 페이지로 사용자가 할 일 한 줄, 그리고 요지 세 줄.
2. **바뀌는 것:** 실제 경로 · 파일 이름 표(생김 · 바뀜 · 옮김 · 지움), 전 → 후.
3. **실제 내용:** 파일 전문을 접힌 상자로(`filebox`, 실제 파일에서 읽음 — 요약으로 대신하지 않는다). 긴 파일은 바뀐 줄을 먼저.
4. **결정과 근거:** Claude가 정한 것과 버린 대안 한 줄씩.
5. **사용자 칸:** 질문 둘 이하(추천값과 함께) + 전체 표시 + 메모.
6. 끝: 끝남 · 남음, 누가.

## 2b. 올리기 전 고정 단계 — `wf-second-look`
페이지를 사용자에게 링크로 주기 전에 **항상** `wf-second-look`에게 페이지의 원천 파일(설계 · 결론 문서)과 요구 원문(사용자 원문 · 이전 피드백 경로)을 주고 다시 읽힌다. 지적은 고치고, 고치지 않은 것은 페이지의 "결정과 근거"에 이유와 함께 적는다. 상태판처럼 판단이 없는 페이지(실제 파일 목록 · 진행 상태만)는 건너뛴다. (판단에 맡기면 불리지 않으므로 고정 단계로 둔다.)

## 3. 만드는 법
- 생성 script는 공용 도구 `~/.claude/workflow/tools/review_page.py`의 함수(마스킹 · filebox · 표 · 표시 칸 · db 저장 JS)를 import해 주제의 `exec\` 또는 `00_META\pages\`에 쓴다. 페이지 내용을 손으로 HTML에 적지 않는다(다음 라운드에 다시 구울 수 없다).
- 금지어는 굽는 단계에서 가린다(redact 원천, 절 1). 공개 artifact가 아니어도 가린다.
- 표시는 artifact db의 모음 하나(`<주제>_<라운드>_marks`)에 저장한다. publish 때 `capabilities: {db: {}}`.
- 라운드마다 같은 파일 경로로 다시 굽고 다시 publish한다(같은 URL). 링크와 상태를 채팅에 한 줄로.

## 4. 표시 읽기
사용자가 "답함"이라고 하면 db 모음을 읽고, 원문을 그 주제의 기록 파일에 고치지 않고 옮긴 뒤(누가 · 언제 · 표시 · 메모) 반영한다. 메모가 판정을 뒤집으면 decisions에 superseded로.
