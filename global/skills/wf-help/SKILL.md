# wf-help

답의 재료는 지도 넷이다(모두 `~/.claude\workflow\maps\`, 기계가 구움, 손으로 고치지 않음):
| 파일 | 무엇 |
|---|---|
| `wf.md` | WF 사용법: 세션의 순간 표, 설치된 `wf-` skill · agent마다 이름 · 언제 · 부르는 말 예시(각 앞머리의 description에서), 공용 도구 |
| `projects.md` | PC 전체 프로젝트: 이름 · 카테고리 · 경로 · 한 줄 소개 · WF 방식인지 · 마지막 활동 · 다음 첫 행동 |
| `assets.md` | skill · agent · script 전체(주제 것 포함) |
| `knowledge.md` | 주제마다 어떤 지식(결정 · 도메인 · 이해 기록 …)이 어디 있나 |

## 1. 먼저 신선도
지도 머리의 생성 시각이 하루를 넘었으면 `python <core>/tools/map.py --build`(약 10초)로 다시 굽고 답한다. 묻지 않는다.

## 2. 질문의 종류로 답한다
- **"무엇을 쓰나 · 어떻게 말하나":** `wf.md`에서 그 순간의 skill · agent와 부르는 말 한두 개를 낸다. 사용자가 slash를 기억하지 않아도 되는 말(예: "마무리", "아이디어로 저장해")을 먼저 보인다. 아래 3의 표가 기본.
- **"어떤 프로젝트가 있나 · 소개":** `projects.md`에서 카테고리별로. 하나를 물으면 그 줄 + 그 프로젝트의 재진입 카드 맨 위(목적 · 지금 · 다음 첫 행동)만 읽어 보탠다. 문서 전체를 읽지 않는다.
- **"지금 어디부터 하나":** `projects.md`에서 다음 첫 행동이 있고 최근 활동이 있는 것, 기한이 적힌 것을 셋까지 추천. 마지막은 Claude의 추천 하나.
- **"이 skill · 도구가 뭐였지":** `assets.md`에서 찾아 경로와 when 한 줄.
- **지난 결정 · 지식의 내용 자체**를 묻는 질문은 `/wf-ask`로 넘긴다(그쪽이 근거를 읽고 답한다).

## 3. 기본 대화법 (사용자에게 보이는 표)
| 하고 싶은 일 | 이렇게 말한다 | 끼어드는 것 |
|---|---|---|
| 새 일을 시작 | 그 카테고리 폴더에서 `/wf-project-init` + 원하는 것을 한두 문단 | 이해 시트 artifact, 질문 둘 이하 |
| 하던 일로 돌아옴 | 그 폴더에서 "계속" | 세션이 열릴 때 재진입 카드 머리가 보임 |
| 방향이 바뀜 | "다시 init" | `/wf-project-init` 재-Init |
| Claude가 무언가 승인을 청함 | artifact에서 표시하고 "답함" | `/wf-review-page` |
| 전에 한 일 · 정한 것 | "전에 ~ 있었나", "우리가 ~ 어떻게 정했지" | `/wf-ask` |
| 아이디어 | "아이디어로 저장: ~" | `/wf-idea` |
| 재부팅 · 오래 비움 | "복구", "최근 1주일 뭐 했지" | `/wf-recover` |
| 끝낼 때 | "마무리" | `/wf-project-wrap` |
| 모를 때 | "WF 도움", `/wf-help` | 이 skill |

## 지킬 것
- 읽기 전용이다. 지도를 다시 굽는 것 말고는 아무것도 쓰지 않는다.
- `<private-folder>`은 이름과 경로만, 다른 사람의 작업 폴더(`<other-person-folder>`)는 이름과 "다른 사람의 폴더"만 보인다. 지도는 금지어를 가린 채 구워지므로 원문을 다시 읽어 가림을 풀지 않는다.
- 지도에 없는 것은 "지도에 없음"이라고 말하고 짐작으로 채우지 않는다.
