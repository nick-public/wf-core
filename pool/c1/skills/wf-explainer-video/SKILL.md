# wf-explainer-video

여러 주제에 반복해 쓰는 것이 전제다. 한 주제를 사람이 한 번 보고 "이것이 무엇이고 왜 중요한가"를 잡게 하는 것이 목적이다. 그림이 설명서가 되면 실패다 — 장면 하나에 메시지 하나, 자세한 것은 앱 글과 해설판이 맡는다.

## 도구 (영상 일이 열릴 때 주제로 복사)
pool에는 아직 영상 script가 없다. 원본은 RTL WorkSys 앱 repo의 `30_tools\`(지도에서 현재 위치 확인 — 디렉토리 이동 뒤 `C:\C1_Career\<topic>`): 장면 껍데기 `templates\scene_template.html`, 장면 도구 `20_app\media\scene_kit.js`, 그림 · 15초 렌더 `render_media.mjs`, 해설판 합성 `narrate.mjs`(edge-tts) · 배경음 `make_bgm.py`, 공개 gate `gate.sh`. 새 주제는 이것을 복사해 쓰고, 두 번째 주제에서도 바꿀 것이 없으면 pool `common\tools`로 올린다. 규약 원문 `00_META\INFOGRAPHIC.md`가 API · 좌표 · 명령의 정본이다.

## 그 주제의 설정에서 받는 것
주제 id(영문 소문자), 재료 정본(설계 문서 · 인계 문서 · 이미 있는 요약), 앱의 데이터 파일과 그 안의 자리(`maps.<id>` 같은), 앱에서 이어질 곳(링크 대상), 공개 금지어 묶음, 해설판까지 만들지(기본: 만든다).

## 새 주제
1. 재료가 정본으로 확정된 주제만 만든다. 아직 seed면 만들지 않고 무엇이 먼저 필요한지 보고한다.
2. 요지 두세 줄을 메인이 정한다: 이 주제에서 꼭 드러나야 할 "왜 중요한가".
3. agent `wf-explainer-maker`에게 맡긴다(장면 그리기 · 반복 렌더 확인이 컨텍스트를 많이 쓴다). 프롬프트: 주제 id, 재료 경로, 요지, 이어질 곳, 해설판 여부, 도구 경로, 쓸 수 있는 폴더. agent는 배포 · commit을 하지 않는다.
4. 보고를 받으면 **메인이 직접 본다**: 다크 그림 PNG, 15초에서 장면마다 한 장, 해설판에서 몇 장. 대본을 한 번 읽어 사실 · 숫자 · 상태가 원본과 맞는지, 확정 아닌 것을 확정처럼 말하지 않았는지 본다.
5. gate 0건 → 배포 → 라이브에서 미디어 파일과 데이터 항목을 받아 확인 → 경로 명시 commit.
6. 사용자에게: 링크, 15초의 다섯 장면 한 줄씩, 해설판 길이와 구성, "들어 보고 고칠 문장을 말해 주면 그 문장만 다시 합성한다".

## 고치기 (agent 없이 메인이 직접)
- 대본 문장: 그 문장만 고친다 → 해설판 재합성(음성은 문장별 캐시라 바뀐 문장만 다시 만든다).
- 그림 · 15초: 장면 HTML → 그림만 렌더해 확인 → 15초 렌더. **좌표가 바뀌면 대본 tour의 `view` · `box`도 고치고 해설판을 다시 뽑는다.**
- 앱 글만: 데이터 파일만 고치고 배포(렌더 불필요).

## 판정 기준과 주의할 점
- 해설판 분량은 1,600~1,800자(≈4분). "실제 개요, 전반 내용 설명이 가능한 수준" — **짧게 줄이지 않는다**(사용자).
- 숫자 기준(임계값 · 횟수)은 공란이 원칙이다. 건수 · 단계 수 같은 사실은 적어도 된다. 위임으로 정한 가정은 "가정 · 교정 대기"로 말한다.
- 해설판 음성은 edge-tts라 **대본이 Microsoft 서버로 간다.** 회사 · 개인 정보가 대본에 들어가면 안 되는 이유가 하나 더 있다. 업계 용어(영어)는 막지 않는다.
- 해설판 렌더는 10~15분: background로 돌리고, 같은 주제를 두 번 동시에 돌리지 않는다.
- 해설판의 "여기부터 듣기"는 file://에서 시각표 JSON을 못 읽어(CORS) Pages에서만 확인된다.
