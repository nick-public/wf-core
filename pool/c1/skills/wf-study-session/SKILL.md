# wf-study-session

사용자는 시간이 짧고 띄엄띄엄 앉는다. 세션의 값은 "30초 안에 복귀"와 "배운 것이 다시 돌아오는가"에서 나온다. 문답을 원문으로 받아 적는 일, 사용자 도출이 아닌 내용의 표시, 자격시험 범위 잡기는 C1 카테고리 지시에 있으니 여기서 되풀이하지 않는다.

## 그 주제의 설정에서 받는 것
진도 파일(현재 위치 · 다음 진입점 · 복습 큐 · 약점 큐 · confidence), 세션 기록 폴더, 범위 정본(출제기준 · spec · 커버 표), 시험 · 목표 자료의 언어, 공개 피드 폴더(있으면). 없으면 Init이 만든 재진입 카드에서 찾고, 그래도 없으면 첫 세션에 위 칸을 가진 진도 파일 하나를 만든다.

## 열기
1. 진도 파일과 마지막 세션 기록을 읽고 카드를 낸다: 지난 시간 1~2줄(Claude가 요약한다) · 전체 중 지금 위치 · 오늘 목표 1개 · 오늘 소환할 복습 문항.
2. **회상 질문을 강요하지 않는다**(사용자 교정): "지난번 무엇을 배웠죠?" 같은 추상적 워밍업은 묻지 않는다. 묻는 것은 복습 큐에서 소환일이 된 **구체 문항** 2~3개와 약점 큐 문항뿐이다. 첫 세션이면 건너뛴다.
3. 시간 모드를 인자에서 받는다(없으면 한 번 묻는다): 핀치 ~15분(카드 + 복습 + 개념 1 또는 판단 문제 3) · 표준 ~45분(개념 1~2 + 적용 1) · 딥 90분+(개념 2~3 + 실습 + 시나리오 한 조각). 15분만 있어도 진도와 복습이 함께 나가게 자른다.

## 가르치는 방식 — 무엇을 배우느냐로 고른다
- **새 개념:** 직접 · 짧게 · 밀도 높게 설명한다(사용자 교정: 개념 도입을 소크라테스 문답으로 끌면 느리다). 이어서 판단형 문제 하나로 바로 써 보게 하고, 거기서는 사용자가 먼저 답한다. 막히면 힌트 → 정답 순.
- **사용자가 도출해야 하는 칸:** 공개 증류할 설계 사고(datapath · 파이프 · throughput · hazard 같은 일반 아키텍처)는 Claude가 골격과 유도 질문 5~8개만 깔고 한 번에 하나씩 묻는다. 사용자가 도출한 것만 본문이 된다.
- **재복습(2회차 이후):** 1문1답을 쓰지 않는다(사용자 지시). 한 범위(도메인 · 장)를 핵심 · 함정 · 용어까지 한 번에 조밀하게 보이고, 문항을 묶음으로 내 사용자가 한두 번에 몰아 답하게 한 뒤 일괄 채점 · 교정 → 틀린 것만 다시.
- 이해하지 못한 것은 진도로 넘기지 않는다. 개념마다 "이게 시험 · 실무의 어느 결정을 가르나"를 한 줄 붙인다.
- 가끔 그럴듯한 오답을 Claude가 밀고 사용자가 반박하게 한다(판단형 시험 대비).

## 전문가 모드 — 항목 하나를 최고 전문가 수준으로
사용자의 C1 목표: "RTL engineer로서 지식과 경험의 깊이와 폭을 모두 넓히고, 손대는 모든 항목을 최고 전문가 수준의 이해도로 다가간다." 시험 모드(아래 · 위 절)는 범위를 덮는 일이고, 이 모드는 한 항목을 바닥까지 파는 일이다.
1. **1차 자료에서 출발:** 그 항목의 spec 절 · 원 논문 · RTL 원문 · 표준을 `wf-researcher`(바깥) 또는 직접 읽기(주제 안)로 모은다. 요약 · 블로그로 대신하지 않는다. 근거는 절 번호 · `file:line`.
2. **구조:** 무엇이 무엇과 어떻게 이어지나 — 블록도 · 데이터 흐름 · 제어 흐름을 한 장으로. Claude가 그리고 사용자가 고친다.
3. **설계 판단:** 왜 이렇게 설계했나 · 대안은 무엇이었나 · trade-off(면적 · 전력 · 지연 · 대역폭 · 검증 난이도)와 숫자. 이 칸은 사용자가 먼저 답하고 Claude가 반박 · 보강한다(사용자 도출 칸).
4. **사용자 설명:** 사용자가 그 항목을 시니어 설계자에게 설명하듯 한 쪽으로 쓴다. Claude는 고치지 않고, 틀리거나 빈 곳만 표시한다.
5. **판단 문제 3개:** "이 조건이 바뀌면 설계를 어떻게 바꾸나" 형식. Claude가 내고 사용자가 답한다.
6. **기록:** 빈 곳 목록 → 다음 진입점, 한 쪽 설명과 판단 문제 결과 → 그 주제의 이해 기록(`knowledge\` 해석 층, 1차 자료 인용). 공개 후보면 `wf-paper-study-app`의 입력이 된다.
**끝 판정(가정, 첫 실사용 뒤 고친다):** 4의 한 쪽에서 Claude가 표시한 틀린 곳이 없고, 5의 판단 문제 3개를 통과.

## 언어 — 시험 · 원자료가 영어일 때
- 대화 · 설명은 한국어로 하되 **핵심 개념 · 정의 · 판별 기준 · 기법 이름마다 영어 원어 + 시험 문장투의 한 줄 영어 정의**를 붙인다. 빠뜨리면 시험장에서 단어를 몰라 틀린다(사용자 지시). 번역어가 모호하면 바로 원어로 고친다.
- 1회차를 다 돈 뒤에는 English-main으로 바꾼다(설명 · 질문 · 정리 영어, 한국어는 뉘앙스만).
- 범위 밖 배경을 넓힐 때는 "배경이고 시험엔 안 나온다"고 표시해 공부와 시험을 가른다.

## 사실의 근거
학습 데이터 이후의 표준 · 코드(새 코덱 spec, 새 API 등)는 기억으로 말하지 않는다. 원문을 열어 `file:line` · spec 절로 보이고, 확인 못 한 것은 "미확인"이라 적는다.

## 닫기
1. 카드: 오늘 1줄 · confidence 변화(개념 X→Y와 근거 한마디) · **다음 진입점 1문장**(다음에 앉으면 바로 할 구체 행동).
2. confidence는 0 안 봄 · 1 들어봄 · 2 이해 · 3 설명 가능 · 4 판단 문제 통과 · 5 남에게 가르침 · 시나리오 적용. 목표는 범위마다 평균 4 이상.
3. 오늘 배운 항목을 복습 큐에 D+1 · D+3 · D+7로, 틀리거나 헷갈린 것을 약점 큐에 넣는다. 범위 정본의 상태 칸만 고치고 본문은 건드리지 않는다.
4. 이해 확인 두 문장을 사용자에게 청한다: "오늘 것을 한 줄로" · "면접에서 이걸 어떻게 소개하나". 사용자의 답은 그대로 적는다.
5. 세션 기록은 요약과 문답 원문 두 벌. 요약에는 **배경 · 오리엔테이션 절**을 따로 둔다: 사용자가 던진 큰 그림 질문("이건 실제로 어디서 쓰나")과 그 설명을 요약하지 말고 남긴다(사용자 지시 — 시험 감각에 중요).
6. 공개 피드가 있으면 증류분만 쓴다(공개 언어 규칙대로). 오답 · 약점 원본은 피드에 넣지 않는다. 다만 문답 번역본의 오답 turn은 지우지 않고 `(wrong)` · `(correct)`로 표시해 남긴다.
7. 앱 세션이 따로 돌고 있으면 앱 repo · 앱 빌드 폴더는 쓰지 않는다. 학습 세션은 진도 · 세션 기록 · 피드 폴더까지만 쓰고, 앱 반영은 앱 세션이 피드를 읽어 한다.
8. 날짜는 환경의 오늘 날짜를 쓴다. 학습 workspace가 로컬 전용이면 push하지 않는다.
