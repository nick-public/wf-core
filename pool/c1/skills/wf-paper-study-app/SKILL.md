# wf-paper-study-app

산출물 셋: 자료(원문은 repo 밖) · 스터디 노트 · 학습 앱. 앱은 엔진(`app.js` · `styles.css` · `index.html`)을 손대지 않고 `assets/content.js`만 채운다. 기업 분석판은 pool `common\skills\wf-equity-scenario-app`(같은 template-copy 방식).

## 그 주제의 설정에서 받는 것
주제 · 키워드, 독자(사용자 자신 · 전공 공개 · 비개발자 수강생), 공개 범위(착수 때 정한 것), 배포 위치(github.io 하위 폴더 · 별도 repo), 기존 노트 폴더.

## 1. 자료
- 후보 3개 이내를 표로(제목 · 저자 · 출처 · 연도 · 무료 여부). 논문 + 특허, 논문 + 후속 논문처럼 짝을 지어 추천할 수 있으면 그렇게.
- 오픈액세스만 직접 받는다: `curl -sL -A "Mozilla/5.0" -o papers/<이름>.pdf <url>` → `file`로 PDF인지 확인 → 1쪽을 Read해 제목 · 저자가 맞는지 본다(HTML 오류 페이지가 .pdf로 저장되는 일이 잦다). 로그인 · 유료 자료는 받지 않고 찾는 법을 안내한다.
- 독자가 비개발자면 쉬운 한국어로 한 번에 한 단계, 전공자면 밀도 높게.

## 2. 노트
`wf-study-session` 전문가 모드로 이미 정리한 항목이면 그 이해 기록(1차 자료 인용 · 사용자의 한 쪽 설명 · 판단 문제)이 노트의 정본이다. 새로 쓰지 않고 그것을 쪼개 챕터로 쓴다.
`study/NN_제목.md`: 서지 전체 · 한 문장 요약 · 문제 · 방법 · 핵심 결과(숫자) · 한 줄 결론 · 한계 · 다음 단계. 본문 복사 금지, 직접 인용은 15단어 미만 · 출처당 1회, 표 · 그림은 수치만 다시 정리, 불확실한 수치는 뺀다.

## 3. 앱
1. `template/`을 프로젝트로 복사하고 `content.example.js`를 보고 `assets/content.js`를 새로 쓴다. 스키마의 정본은 example 파일이다. 색은 `styles.css`의 `:root` 변수만 바꾼다. `APP_ID`는 프로젝트마다 고유하게(진도 저장 키).
2. 챕터 = 노트를 쪼갠 것. 챕터마다 `src`(원문 근거 위치)를 단다.
3. **퀴즈 규칙**(quiz-publish에서 가져옴):
   - 문항 · 정답 · 해설은 노트와 원문에만 근거한다. 해설에 근거 위치를 쓴다.
   - 초급 = 사실 확인, 중급 = 적용 · 분석. 각 5문항 이상, OX는 수준별 40% 이하.
   - 전공 주제면 중급에 설계 관점의 판단 문항을 몇 개 넣는다(이 앱이 남과 다른 이유).
   - 같은 개념을 숫자만 바꾼 문항을 늘리지 않는다. 보기 순서를 섞어 정답 위치가 몰리지 않게.
   - 이미 문항이 있으면 덮어쓰지 않고 더한다.
4. 기계 점검: `node <이 skill>\tools\check_content.mjs assets\content.js` → error 0. 정답 범위 · 중복 문항 · 빈 해설 · 챕터 근거 누락 · 정답 위치 쏠림을 본다.
5. 공개할 앱이면 `--blind <파일>`로 정답을 뺀 사본을 만들어 만든 세션이 아닌 sub-agent가 풀게 하고 대조한다(C1 카테고리 지시의 정답 규칙). 불일치는 문항을 고쳐 해결한다.
6. 로컬 확인: 파일로 열어 콘솔 error 0, 화면은 pool의 화면 시험 도구로.

## 4. 배포
- 공개 전: `.gitignore`에 `papers/*.pdf` · 받은 원문 폴더 · `.claude/settings.local.json`. 공개 금지어 gate(`~/.claude\workflow\tools\redact_check.py`)를 먼저 돌린다. 개인 메모 · 진도 · 세션 기록은 공개 repo에 넣지 않는다.
- **`git add -A`를 쓰지 않는다**(원문 PDF · 메모가 같이 올라갈 수 있다). 앱 파일을 경로로 add.
- 기본 배포는 github.io 하위 폴더 — pool `common\skills\wf-pages-deploy`. 별도 public repo를 새로 만드는 일은 공개 확대라 사용자 승인이 필요하다.
- 라이브에서 모든 파일 200 · 콘솔 error 0을 확인한다.
