# wf-publish-gate

공개물은 사용자의 이름이 붙는 경력 자산이다. 이 gate의 결과는 "push 가능 / 불가"와 고친 목록이다. 정답 가린 사본 재풀이 · 수치 검산 방법 · 링크 확인 기준은 C1 카테고리 지시에 있으니 그 규칙을 이 순서로 실행한다.

## 그 주제의 설정에서 받는 것
범위 정본(공식 guide · spec · 커버 표), 콘텐츠 상태 칸(`draft` → `reviewed`), 챕터 · 문항 규약 문서, 빌드 · 검사 명령, 공개 금지어 목록.

## 순서
1. **정답 키 독립 재도출 (choice 문항, 생략 불가).** 검증자는 `answer`를 보기 전에 문항과 선택지만 읽고 범위 정본의 근거로 정답을 낸 뒤 대조한다. 자기가 만든 문항을 자기가 검증하면 같은 오해가 통과한다 — 그래서 문항이 많으면 문항별로 독립 sub-agent를 띄우고, 만든 세션이 직접 풀지 않는다.
   - 불일치: 문항이 틀렸는지 해설이 모호한지 판정하고 고친다. **키를 조용히 바꾸지 않는다**(보고에 무엇을 왜 바꿨는지 적는다).
   - 복수선택은 정답 집합을 글자 하나씩 맞춘다.
   - 재도출이 흔들리면 그 문항은 모호한 것이다 → 선택지를 다시 쓴다.
2. **사실.** 모든 주장이 범위 정본 또는 1차 문서에 근거하는가. 근거 없는 "항상 · 반드시 · 가장 좋은"(overclaim)을 찾는다. 범위 밖 내용이 "범위 밖 · 배경" 표시 없이 섞였는지 본다. 문항의 연결 칸(어느 범위 항목인가)이 실제 내용과 맞는지 본다. 코드 조각은 컴파일 · 동작 관점에서 읽는다.
3. **진정성(해자).** 사용자가 실제로 이해 · 도출한 수준인가 — Claude가 앞서 채운 흔적(대량 생성의 균일한 문체, 세션 기록에 없는 깊이)을 찾는다. 설계자 경험에서 나온 비유 · 관점 칸이 살아 있는가(이것이 차별점이다). 미리 낸 조사 초안이면 그 표시가 남아 있는가.
4. **커버리지.** 범위 정본의 항목 중 본문 · 문항이 하나도 없는 항목을 나열한다. 없으면 "0"이라고 쓴다. 침묵하지 않는다.
5. **규약 · 링크 · 금지어.** 규약 검사(필수 칸, 순서, 콜아웃 · 체크포인트 형식, manifest 등록)는 사람이 훑지 말고 그 주제의 검사 코드로 돌린다. 검사 규칙을 바꿀 때는 규칙 표 · 검사 코드 · 검사기의 회귀 테스트 세 곳을 함께 고친다. 공개 금지어 gate(`~/.claude\workflow\tools\redact_check.py`)를 돌린다.
6. **승격.** 통과한 파일만 `reviewed`로 바꾸고 빌드 경고 0 · 렌더 확인을 본다. 경로 명시 commit. push는 그 주제의 경계 표가 허용할 때만(없으면 사용자 승인 뒤).

## 판정
- push 불가: 1의 미해결 불일치, 2의 근거 없는 사실, 금지어 1건 이상, 빌드 경고.
- push 가능하되 보고: 3의 의심(무엇이 왜 의심스러운지 한 줄 — 사용자가 볼 곳), 4의 미커버 목록.
- 내용 판단이 필요한 것(해석이 갈리는 설명)은 고치지 않고 질문으로 올린다. 문구 · 형식 수준은 바로 고친다.
