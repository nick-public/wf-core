# wf-explainer-maker

부른 쪽이 준 주제 id · 재료 경로 · 요지 · 이어질 곳 · 도구 경로 · 쓸 수 있는 폴더 안에서만 일한다. 재료 원본은 읽기만 한다. 다른 주제의 장면 · 미디어 · 데이터 항목을 지우거나 덮지 않는다.

## 먼저 읽을 것
1. 규약 문서(도구 repo의 `INFOGRAPHIC.md`) 전체: 산출물 · 장면 규칙 · scene_kit API · 데이터 모양 · 대본 규칙 · 확인 명령 · 함정.
2. 이미 있는 주제 하나의 장면 HTML과 데이터 항목 — 모양을 맞춘다.
3. 재료 파일.

## 순서
1. **제목줄 다섯을 먼저 쓴다:** 문제(이것 없이 하면 무엇이 무너지나) → 구조(무엇이 어떤 순서로) → 작동(누가 정하나 · 어디서 멈추나) → 확인 · 조립(무엇으로 확인하나) → 결론(**왜 중요한가**). 한 줄이 46px에서 한 줄에 들어가야 한다(한글 약 34자 이하).
2. 장면 템플릿을 복사해 그린다. 글이 상자를 넘치면 **글자를 줄이지 말고 문장을 줄인다**(폭은 `K.width`로 잰다). 색은 CSS 변수로만(라이트 · 다크 둘 다).
3. 그림만 렌더 → **다크 PNG를 Read로 직접 본다.** 겹침 · 넘침 · 빈 곳이 없을 때까지 고친다. 라이트도 한 번 본다.
4. 15초 렌더 → 장면 시각마다 한 장씩 뽑아 본다: 자기 장면보다 먼저 보이는 요소(0초부터 보이는 것은 머리 이름표뿐), 제목줄이 비는 순간.
5. 앱 데이터 항목을 쓰고 순서 목록에 더한다(다른 주제 항목은 건드리지 않는다).
6. 해설판 대본: intro 다섯(15초의 장면 구간 그대로) · tour 여섯~여덟(그림 한 부분을 확대, `view`는 16:9, `box`는 view 안) · close 하나. 1,600~1,800자. 문장은 마침표로 끝낸다(자막이 문장 단위로 갈린다). tour 좌표는 3에서 확인한 그림의 좌표로.
7. 새 영어 용어는 발음표(`PRON`)에 더한다. **긴 구를 앞에, 한 단어는 목록 끝에** — 짧은 단어가 앞에 있으면 그것을 포함한 긴 용어의 발음이 깨진다. 발음표를 바꾸면 같은 단어가 든 다른 주제도 다음 합성 때 바뀐다.
8. 해설판 합성(10~15분, Bash timeout 600000, 끝나지 않으면 로그를 보며 기다린다) → 문단 시각 근처를 뽑아 spotlight · 자막(두 줄 이하) · 제목줄 확인, 음량 −16 LUFS 근처.
9. gate 0건.

## 주의할 점
- 해설판에서 장면이 멈추는 자리가 제목줄 교차 순간이면 제목줄이 빈다: 제목줄 시각을 장면 구간과 맞춘다.
- 포스터 모드(`?poster=1`)에서는 입자를 만들지 않게 쓴다. 입자는 결정론 난수로, 위치는 시각의 함수로만.
- 숨겨진 div에서 보드 · 장면을 초기화하면 렌더가 실패한다.
- 여러 줄 Python을 Bash heredoc에 넣지 않는다(따옴표가 깨진다). scratch 폴더에 `.py`로 쓰고 실행한다.
- 장면 HTML · 장면 도구 · 시각표 JSON도 공개 gate 대상이다. 개인 정보 · 회사 고유 정보 · 세션 이름 · 작업 경로 · 라운드 번호를 쓰지 않는다. 확정되지 않은 결정은 "가정 · 교정 대기"로, 숫자 기준은 공란으로.
- 앱 문구와 대본은 한국어 완전한 문장, 영어 용어는 그대로(upstream을 "상류"로 바꾸지 않는다).

## 보고 (마지막 메시지)
만든 파일과 크기, 15초의 다섯 장면 한 줄씩, 해설판 길이와 문단 구성, 직접 본 확인 결과(무엇을 봤고 무엇을 고쳤나), 남은 걱정(발음이 어색할 용어, 원본에서 애매했던 사실), gate 결과.

shell 명령은 목적 하나씩 짧게 나눠 실행한다. `rm -rf` · shell 변수 · 긴 `&&` · `;` 사슬 · 반복문 · 한 줄 heredoc을 쓰지 않는다. 장면마다 한 장씩 뽑는 일은 script 파일로 쓴다.
