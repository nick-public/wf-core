# 핵심 질문 서술 — 넓은 질문 몇 개 공개 + closed-book 서술

목표: 질문마다 필수 키워드가 정해진 순서로 들어간 완전한 답안을 외워서 손으로 쓰게. 준비물의 성격 = 외울 정본 + 답을 가린 채 떠올리는 연습 + 손으로 쓰는 연습.

## 정본
0. `00_fill_blanks.md` — 아이가 못 채운 부교재 빈칸 · 활동 답을 **부교재에 그대로 옮겨 적을 수 있는 문장**으로. 부교재 다른 쪽의 용어를 우선, 통상 교과서 표현이면 그렇다고 표시.
1. `01_answer_keys.md` — 질문마다 `## 질문 N — <원문>` 아래 `### 1)~7)`: 질문 분해(요구 동사 → 답의 구조) · **암기용 뼈대**(번호 매긴 키워드 사슬 — 이것만 외우면 A를 재구성할 수 있어야 한다) · 모범답안 A(만점형, 뼈대 순서, 키워드 굵게, 부교재 문장에서만 합성) · 모범답안 B(압축형, A의 절반 이하) · 채점 키워드(`- [ ] `) · 감점 포인트 · 출제 변형.
2. `02_question_bank.md` — 질문마다 6~7문항, 형태를 섞는다(통째 · 부분 · 비교 · 사례 판별 · 계산 · 용어 정의). 문항마다 배점 · 힌트 1(방향만, 답 노출 없음) · 힌트 2(키워드) · 모범답안 · 채점 키워드 · 돌아갈 곳(질문 · 뼈대 번호). 계산형은 부교재의 실제 수치를 변형.
3. `03_workbook_digest.md` — 범위의 표를 빈칸 없이 완성본으로(아이 답 + 0의 복원). 앱 정리 탭의 원천이므로 표 구조를 유지.
4. `05_rubric_map.md` — 학교가 수행 수준표를 공개했을 때: 질문마다 수준(5 · 4 · 3 · 2) → 조건(`- [3] 조건 → 뼈대 N`, 4 · 5도, 셋 다 있어야 빌드 통과) → 점수를 잃는 전형. 조건은 "이 문장이 있으면 그 점수"로, 학교 문장의 동사(설명 · 비교 · 평가 · 분석 · 유추 · 도출)를 그대로.

## 생성
`build.py`가 템플릿 HTML 두 장(앱 · 프린트)에 위 md를 데이터로 넣는다. 파서가 기대하는 md 모양(소제목 번호, 체크박스, `### Qn-mm [형태 · 배점]` + `- 힌트 1:` …)을 바꾸면 파서도 함께 고친다. 1호 구현이 그 과제 폴더 `10_prep/app/`에 있다 — 두 번째로 쓰이면 pool로 올린다.

## 앱 탭
정리(주제별 접기, 용어 형광) · 핵심 질문(뼈대 → [A] [B], 키워드 형광, 뼈대 가리기 토글) · 연습(문항 먼저 → [힌트 1] [힌트 2] [모범답안] → 키워드 체크 → 점수 → 틀린 것 되풀이, 필터 · 랜덤) · 전날 점검(뼈대를 가린 채 순서대로 재현). 수행 수준표가 있으면 통째 문항의 수준 판정(3점 조건 전부 → 3, 4점까지 → 4, 5점까지 → 5, 아니면 2).

## 프린트 팩
표지 1쪽(채점 규칙 · 전날 저녁 플랜 · 쓰는 법) + 문항당 3쪽(조건 · 뼈대 · 감점 / 모범답안 A · B / 실전 연습지 = 문항 + 볼펜 줄 + 맨 아래 수준 자가 판정). 자가 판정이 다음 쪽으로 넘치면 줄 수를 줄인다.
