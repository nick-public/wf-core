# wf-perf-prep

목적함수는 하나: **마감 안에, 학교가 요구하는 형태로 아이가 재현할 수 있게 한다.** 논술 실력 향상이나 넓은 문제은행이 아니라 완성된 답안 · 풀이의 재현이다. 사용자: "아이에게 시간이 없으니 좋은 도구를 빨리 만들어 아이 손에 쥐여 주는 것이 중요하다."

**이 skill을 쓰지 않는 과제:** 탐구 · 보고서 · 발표처럼 학생이 판단 · 발견하는 과정 자체가 채점되는 과제. 그때는 C2 카테고리 지시(학생 칸을 채우지 않는다)를 따른다. 포스터 · 모형 제작은 체크리스트 문서면 충분하다(앱 불필요).

## 형태 고르기 — 학교 제출 형태를 먼저 본다
| 공지의 모양 | 판 | 참조 |
|---|---|---|
| 채점 체크리스트 공개 + 손글씨 서술(계산 · 자료해석이 섞여도) | 체크리스트 논술 | `forms\checklist-essay.md` |
| 넓은 핵심 질문 몇 개(성취기준 문장) 공개 + closed-book 서술 | 핵심 질문 서술 | `forms\key-questions.md` |
| 책 한 권 · 한 장을 읽고 공개 문항에 원고지 분량으로 | 독서 논술 | `forms\reading-essay.md` |
| 예시 문항 공개 + "실전은 숫자만 바뀐다" 수학 | 유형 고정 수학 | `forms\math-variant.md` |
| 단어 · 표현 목록 공개 + 뜻 · 빈칸 · 영작 시험 | 단어 암기 | `forms\word-list.md` |

어느 행에도 맞지 않으면 가장 가까운 판의 **패턴만** 빌린다(지난 과제의 앱을 통째로 재사용하면 과하다 — 예: 개념 애니메이션이 필요 없는 과제). 형태가 새로 하나 생기면 이 표에 행을 더한다.

## 그 주제의 설정에서 받는 것
과제 폴더(공지 원본 `00_notice/` · 받은 자료 `inbox/` · 준비 `10_prep/` · 제출 형태 `90_output/`), 공지 원문(문항 · 배점 · 분량 · 시간 · 감점 조항), 자료 정본(교과서 · 부교재 · 책 사진과 아이의 기입 흔적 = 약점 근거), 배포 위치(아이 트랙의 github.io 폴더와 index 카드), 학년 범위. 과제 폴더에 바로 만들고, 상위 공통 폴더는 건드리지 않는다(사용자: 굳이 복잡하게 하지 않는다).

## 공통 뼈대 (한 단계 = 파일 하나, 만들고 다음)
1. **정본 md:** 형태별 판의 정본들(답안 · 문항 · 정리). 키워드 · 사실 · 인용은 **자료 정본에 있는 것만** — 교과서 · 부교재에 없는 용어로 채점표를 만들지 않는다, 책에 없는 사실 · 사진 원문에 없는 "인용"을 쓰지 않는다.
2. **검산:** 정본을 다른 agent(학습 앱 검수 — pool `c2\skills\wf-learn-app-audit`)에 넘겨 사실 오류 · 범위 밖 개념 · 키워드 부정확을 잡는다. 🔴 0이어야 다음. 수치는 script로 재계산, 글자 수는 `len()`으로 실측.
3. **앱 · 프린트는 생성물이다.** 정본 md(또는 생성기)에서 빌드 script가 만든다. 앱 · 프린트를 손으로 고치지 않는다 — 고칠 것은 정본을 고치고 다시 빌드한다. 데이터는 빌드 때 파일 안 JS 객체로 넣는다.
4. **gate:** 인라인 JS `node --check` · 생성된 HTML에 의도하지 않은 태그가 없는지(데이터의 `<`는 이스케이프) · 모바일 규약(viewport, 고정 px 금지, 터치 44px, 640px 분기, 상위 index로 가는 링크) · 검산 🔴 0 · **앱 자기 시험**(`?selftest=1`을 헤드리스 Chrome `--dump-dom`으로 열면 PASS/FAIL 줄이 찍히게 만든다 — 힌트 · 모범답안 · 채점 · 되풀이함 · 가리기 · 점검 흐름) FAIL 0 · 탭별 스크린샷을 본다.
5. **배포:** 아이 트랙 폴더에 앱 · 프린트(+PDF)와 index 카드 한 줄. 배포 repo는 다른 앱 작업과 공존하므로 파일 단위 `git add`, 네트워크 명령은 단독으로. public이므로 학교명 · 아이 이름 · 점수를 넣지 않는다.
6. **첨삭 루프:** 사용자가 넣어 준 아이 답(손글씨 사진 · 타이핑)을 세션 로그에 원문으로 남기고 → 채점 조건 · 키워드 · 분량 대조 → 빠진 조건 · 순서 첨삭 → 정본 보정 → 재빌드 · 재배포.

## 사용자의 교정 (모든 판에 적용)
- **아이를 대화에 끌어들이지 않는다.** "아이에게 물어볼 질문지 · 질문 카드"를 앱 · 프린트에 넣지 않는다. 필요한 확인은 Claude가 채팅에서 사용자에게 정확한 문장으로 묻고, 답이 없어도 준비가 완결되게 만든다(확인이 필요한 조건은 두 경우를 모두 덮는 대비 문장으로).
- **프린트 팩은 한 과제 20쪽 안팎.** 자료 자체에 있는 것 · 앱에 있는 것 · 팩 안의 중복을 뺀다. 문항(주제)당 2~3쪽 + 실전 연습지는 한 쪽에 한 문항. PDF는 헤드리스 Chrome `--print-to-pdf --no-pdf-header-footer`.
- **앱은 끝이 보여야 쓴다.** 시험지처럼 한 페이지에 쭉 나열하고 한 번에 채점(한 문제씩 넘기는 형식은 쓰지 않는다), 유형 · 드릴 · 날짜별 플랜을 늘리지 않는다. 몇 페이지로 나누는 것은 괜찮다.
- **잘 안 외워지는 것 표시 / 해제 + 표시한 것만 추려 보기**, 틀린 문항은 자동 표시(정답 보기 토글은 C2 지시대로).
- 앱 상단에 상위 index 링크와 프린트 팩 · PDF 링크가 눈에 띄게.
- 지도 · 그림이 필요하면 손으로 그린 SVG가 아니라 실제 지도 · 자료(C2 지시).
- 진로 · 가치관 문항에서 아이가 "연결 없음"이라 하면 억지로 잇지 않는다. 아이 취미 · 진로를 억지로 엮지 않는다.
- 아이 기기에는 전송 UI를 두지 않는다(답은 [복사] 버튼으로 메신저에). 진도는 localStorage, 키 prefix는 과제마다 고유.

## 금지
정본 없이 앱 · 프린트에 즉흥 작성. 자료 정본 밖 개념 · 키워드 · 사실. `00_notice/` · `inbox/` 원본 수정. 평가가 갈리는 역사 · 사회 쟁점의 편향 서술(중립으로 나란히).
