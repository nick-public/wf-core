# wf-learn-app-audit

한 번 돌고, 찾은 것을 한 번에 고치고, 끝낸다(재감사 금지 규칙과 검사로 내리는 조건은 C2 카테고리 지시에 있다). 같은 파일을 감사 목적으로 두 번 읽지 않는다. 화면 조작 · 기기 확인은 pool `common\agents\wf-ui-qa`, 완료 조건은 `wf-second-look`가 따로 본다.

## 그 주제의 설정에서 받는 것
대상(데이터 파일 · 앱 · 정본 md · 조사 폴더), 앱 원칙 파일(그 주제의 APP_PRINCIPLES 같은 것 — 산출물 종류마다 다를 수 있다), 독자 수준(본문 깊이 기준과 자극 수위 기준을 따로), 조사 출처, 빌드 명령.

## 1. 먼저 원문을 덤프해 읽는다
렌더된 화면이나 기억으로 판단하지 않는다. 데이터 파일의 본문 칸을 utf-8 텍스트로 뽑아(`PYTHONIOENCODING=utf-8`, script 파일로) 읽는다. 앱이 원문을 옮긴 화면이면 원문과 **단어 · 기호 단위로** 대조한다(요약 비교 금지).

## 2. 관점 — 산출물 종류를 보고 원칙 파일을 고른다
파일 이름 · 경로로 종류를 가른다(풀이 앱 · 연습 앱 · 과제 단계 앱 · 인물 앱 · 에피소드 데이터 …). 종류마다 그 주제의 원칙 파일을 먼저 읽는다. 원칙 파일이 없으면 아래 네 관점만.

네 관점을 병렬 sub-agent로(각자 위반 목록만 내고 고치지 않는다):
1. **사실** — 날짜 · 인명 · 인과 · 수치 · 정답 인덱스. 단정과 추정의 표기. 조사 출처와 대조. 수치 · 정답은 script 재계산.
2. **교사** — 본문 깊이가 독자 수준에 닿는가(너무 얕지 않은가)와 자극 수위가 절제됐는가를 **다른 축으로** 본다(지식 수준이 높다고 수위를 올리지 않는다). 입구는 누구나 들어올 수 있는가, 어려운 말 풀이, 학년 범위 밖 개념.
3. **균형** — 한쪽 시각만 있는가(비서구 · 약소 쪽의 자리), 논쟁은 "이런 시각도"로 나란히, 인물 영웅화 · 폄하, 선택형 활동이 정답을 강요하지 않는가.
4. **편집** — 그 주제의 앱 원칙(점진 공개 · 빈칸 · 톤), 접근성(대비 · 터치 44px · 모바일), 링크 정책, 이미지 라이선스(PD · 명확한 CC, 출처 · alt), 인용 저작권, 개인정보 외부 전송 없음.

선택 — **완결성**(기준 사례로 삼을 페이지 · 단원일 때): 이 페이지만 읽어도 시작 → 전개 → 끝이 닫히나, 큰 사건마다 원인 · 주체 · 결과가 다 있나, 독자의 "누가 · 왜 · 얼마나 · 그래서"에 답하나, 블록끼리 연도 · 인명 · 인과가 어긋나지 않나, 출처 칸에 본문이 잘못 들어가지 않았나. 빠진 곳 · 얕은 곳을 찾는 일이라 사실 관점과 겹치지 않는다. 보통 완결성으로 채운 뒤 네 관점으로 정오 · 수위를 친다.

## 3. 판정과 고치기
| 판정 | 기준 | 처리 |
|---|---|---|
| 🔴 | 사실 오류, 정답 오류, 원문 불일치, 원칙 위반(점진 공개 깨짐 등), 라이선스 불명 | 반드시 고침 |
| 🟡 | 얕음 · 균형 부족 · 접근성 권고 | 고치거나 이유를 적고 넘김 |
| 구조 | 레이아웃 · 기능 구조를 바꿔야 함 | 고치지 않고 사용자에게 보고 |

- **앱이 아니라 데이터(정본)를 고친다** → 다시 빌드. 생성된 앱을 직접 고치면 다음 빌드에서 사라진다.
- 문구 · 속성 수준은 한 번에 일괄로 고친다.

## 4. 통과 gate (모두 체크되어야 배포)
- [ ] 사실 · 정답 오류 0(또는 정정 완료)
- [ ] 본문 깊이 기준 충족, 수위 절제 — 둘 다
- [ ] 관점 균형 확인
- [ ] 앱 원칙 · 접근성 · 링크 정책 · 이미지 라이선스 통과
- [ ] (해당 시) 퀴즈 정답 · 해설, 내보내기 · 인쇄 동작
- [ ] (완결성을 돌렸으면) 원인 · 주체 · 결과, 블록 간 불일치 0
