# wf-exam-review

**한 skill로 묶은 이유:** 노트 · 그림 · 연습 · 약점 DB · 재출제를 각각 skill로 나누면 하나만 불렸을 때 DB 기록이 빠져 학습 고리가 끊긴다. 오답 하나는 끝까지 닫혀야 의미가 있다. 세부 규칙은 같은 폴더의 참조 파일에 두고 필요할 때만 읽는다.

| 파일 | 읽는 때 |
|---|---|
| `app-principles.md` | 풀이 앱 · 연습 앱을 만들거나 고칠 때 |
| `figure.md` | 시험지 그림을 잘라 붙이거나 수학 그래프를 그릴 때 |
| `practice.md` | 연습 문제(3×3)를 만들 때 |
| `retest.md` | 오늘의 재시험 생성 · 채점 반영 · 학습 완료 · 주간 요약 |
| `templates\` | 주제에 처음 깔 때(원인 코드 · 재출제 정책 · DB 레코드 규격) |

## 그 주제의 설정에서 받는 것
과목 → 폴더 매핑, 학기 폴더, 원문(텍스트화한 시험지) 위치, 원본 캡처 위치, 약점 DB · 원인 코드 · 정책 · 내용 태그 어휘의 경로, 학년 범위. 처음이면 `templates\`를 그 주제의 core 폴더로 복사한다.

## 오답 한 문항 (모드: 노트)
1. **정보:** 문항 번호 · 과목 · 쓴 답 · **확신도**(확신 / 반신반의 / 찍음 / 시간부족). 확신도가 없으면 반드시 묻는다 — 이 한 칸이 우선순위와 처치를 통째로 바꾼다(확신인데 틀림 = 오개념, 최우선). 끝내 모르면 `unknown`으로 두고 보고에 적는다. 찍어서 맞은 문항도 받는다. 과목을 모르면 묻는다(추측하지 않는다).
2. **원문:** 텍스트화 파일에서 원문 · 조건 · 보기 · 배점을 읽는다. OCR 의심 표시가 있으면 원본 캡처를 다시 보고, 그래도 불확실하면 사용자에게 묻는다.
3. **원인 진단:** 원인 코드 1~2개(3개 넘으면 진단이 아니라 나열). C3(혼동)이면 `confused_with`를 반드시 채운다 — 쌍이 없으면 구별 훈련을 못 만든다. 판단 근거를 한 줄로 남긴다. 과목의 지배 원인은 그 주제의 `subject_profiles`를 보되, **그 표는 실데이터로 정한 것만 믿는다**(예상으로 채운 표는 실제 원인 분포와 어긋나기 쉽고, 그러면 처방이 바뀐다).
4. **노트** `Q<번호>_<주제어>.md`, 공통 골격: 문제(원문) · 채점(내 답 · 정답 · 배점 · 확신도 · 원인) · 개념 체크(풀기 전 자가 질문 5~7) · 풀이(3~6단계, 단계마다 "왜 이 단계인가", 끝에 검산) · 왜 틀렸나(원인 코드에 근거, "실수했다"로 끝내지 않음) · 핵심 개념 · 재발 방지(원인의 처치) · 태그. 과목별로 하나를 더한다:

   | 과목 | 더하는 칸 |
   |---|---|
   | 수학 | 검산 단계 · 쉬운/중간/어려운 변형 문제 |
   | 과학 | 개념 / 계산 분리 진단 + 단위 점검 |
   | 역사 | 혼동 상대와 나란한 구별표 + 연표 위치 |
   | 사회 | 관점 · 개념 구별표 + 사례 적용 |
   | 국어 | 근거 문장 원문 인용 + 보기마다 근거 위치 |
   | 영어 | 모르는 어휘 목록 + 구문 분해 |

   정답과 풀이만 있는 산출물은 만들지 않는다. 단순화해도 틀린 말은 쓰지 않는다. 학년 범위 밖 개념을 쓰지 않는다. 비표준 기호는 첫 등장에 풀이를 붙인다.
5. **약점 DB 기록**(빠뜨리면 이 skill을 쓴 의미가 없다): `templates\weakness_db.md` 규격으로 append, `counts` 갱신. 같은 id가 있으면 새로 만들지 않고 history에 더한다. 내용 태그는 통제 어휘에서만.
6. **첫 일정:** `first_due = 오늘 + clamp(확신도.first_interval_days + 원인.retest_bias_days, 1, 14)`. 찍음 또는 C2(지식부재)는 `learning`(배우기 전에는 출제하지 않는다 — 다시 물으면 또 찍는다), 나머지는 `scheduled`.
7. **보조 산출물:** 수학은 풀이 앱(`app-principles.md`) → 그림이 있으면 `figure.md` → 연습 `practice.md` 순으로 함께 만든다. 다른 과목의 풀이 앱은 요청할 때만.
8. **보고:** 노트 경로 · 태그(내용 / 원인 / 확신도) · DB 기록 완료 · 다음 재출제 날짜와 이유 한마디.

여러 문항이면 한 문항씩 1~8을 끝까지 돌리고 다음으로 간다. 한 번에 다섯 문항 넘게 받으면 나눠 처리한다. 수학적 오류가 의심되면 그 문항에서 멈추고 보고한다. 다른 학년 주제는 같은 절차에 학년 범위만 바꾼다.

## 지킬 것
- 원본 캡처를 고치거나 지우지 않는다. 기존 노트 · 앱을 덮어쓰기 전에 사용자에게 확인한다. 사용자가 손으로 둔 파일은 그대로 쓴다.
- 아이를 깎는 표현을 쓰지 않는다. 오답은 데이터다("또 틀렸네"가 아니라 "여기 한 번 더 보자").
- 데이터의 구멍을 숨기지 않는다: 옛 노트를 소급 입력하면 "내 답 · 확신도"가 비어 있다. `gaps`에 적고, 다음 시험에서 문항별 쓴 답 · 정오 · 확신도를 받을 방법을 사용자에게 먼저 제안한다.
