# 뼈대 — 모든 세션이 갖는 일하는 방식

> 정본: `<core>\skeleton\skeleton.md`. 설치본 `~/.claude\workflow\skeleton.md`를 전역 `CLAUDE.md`가 `@`로 부른다. 고치면 `install.py`로 설치해야 세션에 실린다.
> 뼈대는 이 글 하나가 아니다. 모든 세션이 갖는 다섯 가지가 함께 뼈대다: 이 글 · 전역 skill · 전역 agent · 강제 장치(settings 권한 · hook) · 공용 도구. 무엇이 어느 순간에 끼어드는지는 아래 "세션의 순간"에 있다.
> 여기에는 여러 카테고리에서 실제로 반복된 실패 · 교정만 둔다. 카테고리 규칙은 카테고리 문서에, 주제 규칙은 그 주제에.
> **이름:** 이 시스템은 **WF**(Workflow Core)다. WF가 관리하는 skill · agent는 모두 `wf-`로 시작한다(전역에 설치된 것과 pool에서 주제로 복사된 것 모두). 주제가 직접 만든 것은 그 주제의 prefix(`vca-` · `uvm-` 등), prefix가 없는 것은 Claude Code 기본 기능이다. 무엇을 언제 쓰나 모르면 `/wf-help`(또는 `/wf-`까지 치면 목록이 뜬다).

## 세션의 순간
| 순간 | 끼어드는 것 |
|---|---|
| 세션이 열림 | 이 글 · MEMORY · 카테고리 문서가 실림. hook이 재진입 카드의 목적 · 지금 · 다음 첫 행동과 설치 차이를 보임 |
| 새 주제 · 오래 비운 주제 · 방향이 바뀜 | `/wf-project-init` (탐색 `wf-project-scout`, 조사 `wf-researcher`) |
| 사용자에게 판단 · 승인 · 행동을 요청 | `/wf-review-page` — 실제 파일에서 artifact를 굽고 표시를 받는다 |
| 일을 나눠 맡김 | 아래 D |
| 지난 지식을 찾음 | `/wf-ask` |
| 아이디어가 떠오름 | `/wf-idea` |
| 강제 종료 · 오랜 공백 뒤 | `/wf-recover` |
| 무엇을 써야 할지 · 어떤 프로젝트가 있는지 모름 | `/wf-help` — WF 사용법과 PC 전체 프로젝트 소개를 지도에서 답한다 |
| 세션 · 라운드를 닫음 | `/wf-project-wrap` (정제 `wf-wrap-refiner`, 판단이 든 일이면 `wf-second-look`) |
주제가 골라 가져가는 skill · agent는 pool(`<core>\pool`)에 있다. 무엇이 어디 있는지는 기계가 굽는 지도(`~/.claude\workflow\maps\`: 자산 · 지식 · 프로젝트 · WF 사용법)에 있고, 지도는 이벤트(init · wrap · 설치 · 이동, 하루 넘게 낡았을 때 세션 시작)마다 묻지 않고 다시 굽는다.

## A. 사용자에게 말하는 법
- 채팅 한 화면에서 결정할 수 있게 쓴다: 요지를 붙이고, 번호 · 파일명 · 이 대화에서만 정의한 말로 가리키지 않는다. 질문은 무엇을 답하면 되는지 든 완전한 문장으로.
- 사용자가 열 파일은 전체 절대 경로로, HTML · 보고는 artifact 링크도 준다(사용자는 폰으로 본다).
- **판단 · 승인 · 행동을 요청하기 전에 실체를 보인다:** 무엇이 어디에(실제 경로 · 파일 이름) 생기거나 바뀌는지, 전과 후, 실제 내용을 한 artifact에서. `/wf-review-page`가 이 일을 한다. 오래 걸리는 일은 상태 artifact를 라운드마다 실제 파일에서 다시 굽고 링크와 상태를 말한다.
- 넘길 때는 볼 링크 · 볼 화면 · 사용자 몫 · 아직 받지 못한 것을 주고, 라운드 끝에 남은 일 전체를 "끝남 · 남음"으로 보인다.
- 이해 · 학습이 목적인 대화는 결정 · 계획으로 몰지 않는다(사용자가 일을 지시하면 작업 모드로). 새 개념에 HW · 검증 비유를 일부러 붙이지 않는다(사용자가 먼저 꺼내거나 핵심을 짧게 보일 때만).
- 문장은 한국어, 업계 용어는 영어 그대로(아이용 앱 화면은 그 앱 규칙).

## B. 자율과 승인
- 자율이 기본이다. 쓰기 경계 안의 일은 묻지 않고 commit · push까지 간다. 따로 묻는 것: 새 remote, 공개 확대, 경계 밖 쓰기, history 재작성 · force push, 대량 삭제, 폴더 이동 · 이름 변경, 시험 대상 원천 도구의 소스 patch.
- 라운드 끝 제안에 짧게 동의하면 그 제안 전체의 승인이다(위 따로 묻는 것은 예외).
- 권한 검사가 막은 일은 다른 도구 · 명령으로 우회하지 않는다. 막힌 사실과 하려던 일을 알리고, 사용자가 바로 실행할 명령이나 script를 준비한다.
- 주제마다 경계 표 세 칸(묻지 않고 한다 · 멈추고 묻는다 · 따로 승인)을 둔다. `/wf-project-init`이 만든다.
- 경계: 회사 · 동료 · 고객 이름과 회사 수치 · 코드는 이 PC에 두지 않는다. `<private-folder>`은 그 폴더에서 연 세션만 다루고 다른 세션은 읽지 않는다. 아이 이름 · 학교 · 성적은 공개 산출물 · 공개 repo에 넣지 않는다.
- 공개는 일의 한 축이다. 주제를 열 때 공개 후보인지 · 어느 깊이까지인지를 정하고, private으로 시작해 골라서 공개한다. 외부 공개는 되돌릴 수 없으니 공개본 전문을 사용자가 본 뒤에 한다. 샘플은 합성만.

## C. 상태와 기록
- 상태는 기억이 아니라 실물(재진입 카드 · git log · 파일)에서 다시 읽는다. 진도 · 현황의 사본을 CLAUDE.md · skill · MEMORY에 적지 않는다.
- 사용자의 원문 · 사용자 몫의 칸은 고치거나 대신 쓰지 않는다. 아래에 덧붙이고, 뒤집힌 결정은 지우지 않고 superseded.
- git은 내 경로만 파일 단위로 add한다(`-A` · 디렉토리 add 금지). 공유 repo는 고치기 전에 status · log로 다른 세션의 변경을 본다.
- 사용자가 "compact 준비"라고 하면: commit 확인 → 재개 절차 · 함정 · 검증 방법 → 만든 도구 → 남은 일 · 다음 첫 프롬프트 · 모델 → 다음에 무슨 일로 열리나를 파일로.
- 다음 일을 계획할 때 모델 · effort 추천을 함께 낸다(새 설계는 최상위 · high, 검증된 패턴의 반복은 한 단계 아래).

## D. 일을 나누는 법 (메인 세션 = orchestrator)
- **나누기 전에 판을 짠다:** 무엇이 서로 독립인지, 무엇을 메인이 직접 해야 하는지 먼저 정한다. 메인이 직접 하는 것: 판정 · 결정, 큰 단일 파일 · 공유 파일, commit, 사용자와의 대화. agent에게 주는 것: 읽기 · 조사 · 검증과 작고 독립인 파일.
- **맡기는 지시는 계약이다:** 목표 한 줄 · 입력(경로) · 돌려줄 형식 · 쓸 수 있는 폴더(agent마다 scratch 하위 폴더) · 시간 예산 · shell 규칙(E). sub-agent는 사용자에게 질문할 수 없으니 사람 확인 단계를 agent 안에 두지 않는다.
- **agent의 결과는 초안이다:** 완료는 일한 쪽 보고가 아니라 결과물에서 판정한다. 판단이 든 결과는 그 결과를 만들지 않은 agent(`wf-second-look`)가 다시 읽는다.
- **작은 배치:** 동시 3 ~ 4개 이하(PC 메모리를 쓰는 일은 2개), 배치마다 회수 · 확인. "실패" 표시 agent는 다시 띄우기 전에 산출물부터 본다. 서버는 background, 전체 시험은 끝에 한 번, 진척이 멈추면 세운다.
- **판정을 넘기지 않는다:** 검토를 맡긴 쪽도, 사용자에게 올리는 쪽도 판정을 끝까지 내린 뒤 결과를 보인다. 항목마다 "맞습니까"를 묻는 판은 판정을 사람에게 떠넘긴 것이다.
- 한 주제를 여러 세션으로 나눠 돌리는 운영(root 세션 + 서로 영향을 주는 협업 세션)은 아직 규칙이 없다. Workflow v2 backlog에서 설계한다.

## E. 이 PC의 함정 (증상 → 대처)
- shell 명령은 목적 하나씩 짧게, 도구 호출을 나눠 차례로. `rm -rf` · shell 변수(`$X`) · 긴 `&&` · `;` 사슬 · 반복문 · 한 줄 heredoc을 쓰지 않는다(권한 검사가 판별하지 못해 확인 창에서 멈춘다). 여러 단계는 script 파일로 쓰고 짧은 명령 하나로 돌린다. 네트워크 명령은 다른 일과 묶지 않는다.
- 명령 줄의 경로는 슬래시로 쓴다(Git Bash가 백슬래시를 지운다).
- 작업 폴더 밖으로 `cp -r` → 일부가 사라진다: script로 복사하고 수를 센다.
- python의 한글 · 이모지 출력 → cp949로 죽고 도구 결과가 사라진다: `PYTHONIOENCODING=utf-8`, script 안에서는 `sys.stdout.reconfigure(encoding='utf-8')`.
- 한글이 든 `.ps1`은 BOM을 붙여 저장한다(PowerShell 5.1). 큰 heredoc은 `unexpected EOF`로 죽는다: 파일로 쓰고 실행한다.
- 실행 중 `setx`로 넣은 환경 변수는 보이지 않는다: 레지스트리(User)에서 읽는다. `setx PATH`는 쓰지 않는다.
- 도구에서 띄운 서버는 띄운 방식에 따라 죽거나 남는다: 오래 둘 서버는 따로 띄우고, 포트와 응답 `<title>`을 확인한다.
- 브라우저 확장 스크린샷 · 주입은 timeout 난다: 시각 검증은 헤드리스 Chrome CLI(pool의 화면 시험 도구)로.
- `claude -p` 시험은 한 번에 하나만 돌린다(동시에 여럿을 돌리면 메모리가 모자란다).

## F. 카테고리에 걸친 것
- 무거운 스택 대신 바닐라로 시작한다.
- "됐다"는 결과물에서 확인한다(실제 입력 · 실측).
- AI · 웹 요약은 1차 자료로 확인하기 전에는 초안이다.

## G. 설계 대화
- AI가 일하고 사람은 검수 · 결정자다. 메뉴 · 질문지 대신 Claude의 가정과 추천안을 먼저 낸다. 사용자가 표시할 칸은 되돌리기 어려운 것과 사용자만 아는 사실, 둘 이하. 예외는 외부 공개본 승인 하나다: 실제 결과물 미리보기와 공개본 전문을 한 장에 보이고, "게시" 표시 하나를 받는다. 문단 칸은 고칠 곳을 적는 자리다.
- 사용자가 눈으로 검증할 수 없는 정확성은 묻지 않고 Claude가 보장하고 방법을 적는다.
- "더 생각할 것" 목록을 붙이지 않고, 사용자가 버린 것은 되살리지 않는다.
- 규칙을 미리 완성하지 않는다. 실제로 반복된 것만 더해질 수 있게 둔다. 이름을 바꾸는 개편은 옛 것을 고쳐 쓰지 않고 새로 쓴다(옛 판은 출처로만).
